# Nckik′s music 0.4.0

Windows 桌面播放器，Electron + 原生 Web Audio。单窗口、单界面，打开即播。

## 安装（把程序放到别的电脑上）

产物：**`dist/NckiksMusic-Setup-0.4.0.exe`**（约 89 MB，Windows x64，已内含 Electron 运行时与全部依赖，目标机不需要装 Node.js）。

1. 把 `NckiksMusic-Setup-0.4.0.exe` 拷到目标电脑（U 盘 / 局域网共享都行）。
2. 双击运行；安装向导里可以改安装目录（默认 `%LOCALAPPDATA%\Programs\Nckik′s music`）。
3. 装完桌面与开始菜单会出现「Nckik′s music」快捷方式，双击即可用。
4. 卸载：设置 → 应用 → Nckik′s music → 卸载，或运行安装目录里的 `Uninstall Nckik′s music.exe`。卸载**不会**删用户数据。

安装包是**未签名**的，首次运行 Windows 可能提示「未知发布者」：点「更多信息 → 仍要运行」即可。这是没有代码签名证书的正常现象，不是文件损坏。

用户数据位置（曲库、设置、登录凭证）：

| 运行方式 | 数据目录 |
| --- | --- |
| 安装包安装后 | `%APPDATA%\NckiksMusic\` |
| 源码 `npm start` | `%APPDATA%\NckiksMusic\`（同一目录，便于两种运行方式共用曲库） |

`library.json`（曲库）、`settings.json`（设置）、`ne-auth.bin`（加密后的音乐平台凭证）、`crash.log`（主进程异常日志，出问题时先看它）。删掉整个目录即恢复出厂状态。

## 源码运行

在项目根目录双击 **`启动播放器.bat`**（会先检查依赖，缺了自动 `npm install`）。

或命令行：

```
cd player
npm install      # 首次
npm start
```

重新打安装包：`npm run dist`（会先生成图标，再出 `dist/NckiksMusic-Setup-<版本>.exe`）。

首次启动会看到一个空曲库，封面区域可直接点击导入，也可以把音频或文件夹拖进窗口。

## 明确没实现（设置页里标为「未接入」，不是藏起来）

- **USB 独占 / 位完美**：需要 WASAPI Exclusive，得下沉到 Rust/C++ 原生层。当前走 Chromium 的系统混音。
- **无缝播放 / 淡入淡出 / EQ**：`<audio>` 不支持双解码器预读与音频图插入。
- **采样率锁定**：无。

设置里凡是做不到的都写「未接入」并给出原因，没有做成能点但没用的开关。

## 字体

全局使用 **苹方（PingFang SC Medium）**：`assets/fonts/PingFangSC-Medium.ttf`，随安装包一起分发（`build.files` 里不再排除）。

- `@font-face` 用 `font-weight: 100 900` 声明，整个字重区间都取这一个文件，避免浏览器合成假粗体；
- 全局只在 `:root` 定义一次 `--font-ui`，正文、按钮、输入框、弹层全部走它 —— 表单控件默认不继承 body 字体，所以对 `button / input / select / textarea` 单独指定了一遍，否则「导入文件 / 搜索框 / 音质档位」会掉回系统字体；
- `font-display: swap`：字体 11 MB，万一文件缺失或损坏，也不会出现「有布局没文字」，先显示系统字体再替换；
- 兜底栈 `Microsoft YaHei UI → Segoe UI → system-ui`，保证极少数苹方缺字（如个别符号）时也有字形可用。

**授权**：苹方是 Apple 的商用字体。本版本按需求把它打进了安装包，若要把安装包再对外分发/商用，请自行确认字体授权。

## 启动脚本注意事项

`启动播放器.bat` 必须满足两个条件，否则 cmd 会把文件拆成碎片执行，报一串"不是内部或外部命令"：

1. **换行必须是 CRLF**。只有 LF 的批处理文件，cmd 解析会错位，命令被从中间截断（例如 `--no-audit` 被切成 `o-audit`）。
2. **内容只使用 ASCII**。用 UTF-8 存中文、又没有 BOM 和 `chcp` 的情况下，cmd 按本地代码页解析，提示语会变乱码甚至干扰解析。因此脚本内提示语全部用英文。

脚本已在启动前清掉 `ELECTRON_RUN_AS_NODE`，避免某些环境预设了该变量导致 Electron 退化成纯 Node 运行、窗口不出现。

## 歌词进度：为什么是单层文字

早先的实现是「底层白字 + 上层主色字 `clip-path` 擦除」。夜间模式下能看到主色字边缘透出一圈白边——两层文字各自抗锯齿，主色字的半透明边缘把下层白色露了出来。另外两层必须像素级对齐，字号一过渡就有错位风险。

现在只有一层文字：

```css
.ln {
  --p: 0%;
  width: max-content; max-width: 100%;
  background-image: linear-gradient(90deg, var(--lc1) 0 var(--p), var(--lc2) var(--p) 100%);
  -webkit-background-clip: text; background-clip: text;
  color: transparent;
}
```

紫色与白色由同一份字形一次栅格化，边界是一条干净的竖切，没有描边也没有重影。`width: max-content` 让渐变百分比与文字宽度对应，`--p` 到 100% 时正好是「这句唱完」。

进度由 `requestAnimationFrame` 逐帧写入，但时间源不是 `audio.currentTime`（它只有约 4Hz 的更新粒度）：

```js
const guess = clock.base + (now - clock.wall) / 1000;   // 用 performance.now 插值
if (Math.abs(guess - real) > 0.3) { /* 漂了就以真实值重新锚定 */ }
```

实测进度更新频率从 4 次/秒提升到每帧一次，且不会累积漂移。

## 全屏

`setFullScreen(true)` 是原生全屏，会盖住任务栏。没有采用「放大到屏幕尺寸 + 置顶」——那种做法要么盖不住任务栏，要么压住所有其他程序。

退出时要精确还原，尤其要覆盖「最大化状态下进入全屏」：

```js
preFull = { maximized: win.isMaximized(), bounds: win.getNormalBounds() };
// leave-full-screen 时：原来最大化就 maximize()，否则 unmaximize() 后 setBounds(bounds)
```

只在退出时调 `setFullScreen(false)` 不够——Windows 上最大化进全屏、退出会掉成普通窗口。

快捷键：`F11` 切换，`Esc` 退出（全屏时 Esc 优先退全屏，不会误关抽屉）。鼠标移动时右上角会浮出「退出全屏」，静置 2.2 秒淡出。

## v0.2 修复记录（代码审查后）

对照 `音乐播放器代码审查报告.md` 逐条修，全部用隔离探针做过回归（同一份渲染层、独立 `userData`、真实播放断言）。

### 播放正确性

- **路径含 `%` 的曲目放不了**：`media://` 处理里对已解码的参数又 `decodeURIComponent` 了一次，裸 `%` 直接抛 `URIError` 被吞成 400。已去掉重复解码，并把非法路径/非音频扩展名分别返回 400/415。
- **内嵌歌词永远为空**：歌词提取被误关在 `if (withCover)` 分支里，而 `track:lyric` 传的是 `false`。已把歌词解析与封面解耦，并把歌词请求改成轻量解析（不读封面、不算时长）。
- **切歌竞态**：`playIndex` 每一步 `await` 之后都校验递增的 `loadSeq`；`AbortError`（被新的加载打断）不再当成播放失败。`S.playing` 改为由 `play` / `pause` 事件驱动，图标不会再和真实状态脱节。
- **坏文件不再掐断播放链**：解码失败自动跳到下一首，连续 3 次失败才停下并提示。
- **导入时排序导致索引错位**：`mergeTracks` 排序前记住当前曲目路径，排完按路径复位 `S.i`。

### 性能与内存

- **扫描不再读封面**：`lib:scan` 传 `withCover = false` 时整块 sidecar 扫描被跳过；同目录通用封面按目录缓存，一张 `cover.jpg` 只读一次。
- **扫描并发 + 进度 + 取消**：主进程 `mapLimit(6)` 并发解析，边扫边发 `scan:progress`；气泡实时显示「正在读取 N/M · 点此停止」，点击即取消（已解析的部分会保留）。
- **曲库渲染**：去掉 `items.map` 里的 `indexOf`（O(n²)），改事件委托；切歌只改高亮行（`markCurrent`），不再整表重建；`.item` 加 `content-visibility: auto`；搜索输入 110ms 防抖。2000 首实测：整表 124ms → 29ms，过滤 70ms → 17ms，切歌 3ms → 0.1ms。
- **封面不再常驻**：内嵌封面进 LRU（上限 10 张），不再永久挂在曲目对象上。
- **进度条改合成层**：`.fill` 用 `transform: scaleX()`、旋钮用 `translate3d()`，去掉 `width` 过渡。既不再逐帧触发布局，也消掉了填充比歌词慢约 120ms 的错位。

### 交互与健壮性

- 拖拽被系统打断（`pointercancel` / 失去捕获）时 `seekDrag` 会复位，时间气泡不再卡住。
- 长按空格不再高频切换播放/暂停（`e.repeat` 过滤，方向键保留连按快进）。
- 拖入文件夹可直接导入（原来只认文件）；拖拽遮罩在窗口外松手也会复位。
- 设置页新增**位置**（纬度, 经度）输入，自动日夜不再写死上海。
- 随机播放记住走过的顺序，「上一首」是真的上一首。
- 设置写入改为临时文件 + rename 原子替换；JSON 损坏会改名留档而不是静默清空曲库；关窗时补写防抖窗口内的最后一笔改动。
- 单实例锁：重复启动会聚焦已有窗口，不再抢设备。
- `MediaSession` 补齐 `seekto` / `seekbackward` / `seekforward`，artwork 不再谎报尺寸。
- 元数据解析失败的曲目会在副标题与音质弹层里标明「解析失败」，不再显示成 0:00 无从判断。
- 渲染进程开启 `sandbox`，页面加 CSP（`default-src 'none'` + 白名单），`media://` 只接受音频扩展名。

## v0.3 全屏版面重排

问题：全屏时封面被 `62vh` 卡住、页脚写死 `158px`，封面下方到进度条之间会空出一大块，看起来"内容浮在上面"。

改法（`renderer/app.css` 的 `/* 全屏 */` 段，全部收在四个变量里）：

- `--cov` 封面边长 = `clamp(200px, min(42vw, 100vh - 300px), 980px)`，**同时就是歌词列的 height**。两列都 `align-items: center`，当前句的垂直中心因此与封面中心严格重合（实测各尺寸偏差 ≤ 2px）。
- 歌名组改成 `position: absolute` 挂在封面下方，不再参与居中。它一占位就会把封面顶高半个歌名的高度——这正是原来"偏上"的直接原因。`.stage` 底部预留 `--meta + --metagap` 补回这部分空间。
- 页脚从固定 158px 改为 `grid-template-rows: 1fr auto` + 内容自适应，间距用 `clamp(8px, 1.4vh, 18px)`。
- 字号跟随宽度缩放：`clamp(21px, 1.55vw, 38px)` / 当前行 `clamp(29px, 2.5vw, 62px)`。
- `resize` 和进出全屏后，都在字号过渡（0.4s）结束后再调一次 `centerLine()`，否则居中位移差几像素。

顺带修掉窗口模式的一个老问题：`@media (max-width: 980px)` 把封面固定成 `320×320`，窗口压到最小 `860×560` 时歌名会直接压到进度条上（实测重叠 69px）。现在该断点与基础样式的封面宽都带 `calc(100vh - 316px)` 上限，窗口模式任意允许尺寸下歌名与进度条至少留 6px。

实测（隔离探针，改尺寸后回读包围盒）：

| 窗口 | 封面 | 占高 | 封面中心 ↔ 当前句 | 歌名底 → 进度条 |
| --- | --- | --- | --- | --- |
| 1280×620 | 320 | 52% | +1px | 60px |
| 1366×768 | 469 | 61% | −2px | 53px |
| 1920×1040 | 740 | 71% | −1px | 25px |
| 2560×1400 | 980 | 70% | 0 | 82px |
| 1707×1067（真全屏） | 717 | 67% | −4px | 57px |

## v0.4 两个设计问题的真正修法

方案 12.3 原来记的两个问题，只修了"那一张封面 / 那一种情况"，规则本身还留着坑。

### 1. 擦除色补上对比度下限

`--acInk` 是拿主色去对歌词正文色做擦除，等于"同一句话两种颜色"，两者对比度不够就等于没做。原来只固定混白 12% / 混黑 18%，对主色亮度没有任何约束——碰到白底专辑、雪景、米色设计（主色比 `#8F8F94` 还亮），与白字的对比度只有 1.0–1.5，分界肉眼看不出。

`inkFor(accent, dark)`：初始值仍是 12% / 18%，然后用 WCAG 相对亮度校验与 `--fg` 的对比度，不足 **2.4** 时沿同一色相反向压（夜间压黑、日间提亮），仍不足才退到纯黑/纯白。色相不变，整屏仍只有一个颜色。

实测（`renderer/app.js` 里的真实函数，非重写）：

| 主色 | 旧 | 新 | 对比度 |
| --- | --- | --- | --- |
| `#F2EDE2` | `#F4F2ED` | `#A09C95` | 1.03 → 2.40 |
| `#F7D154` | `#F8D769` | `#B79B3E` | 1.29 → 2.48 |
| `#6C5CE7` | `#7E70EA` | 不变 | 3.58 |
| `#2B2B31` | `#44444A` | 不变 | 8.88 |

常规彩色封面取色结果与改动前**完全一致**，只有病态亮/暗的封面会被修正。

### 2. 歌词居中的三处漏算

- 补白改**固定半高**（原来按 `(容器高 − 本行行高)/2`，每行都变；padding 不受 transition 控制、transform 有 0.55s 过渡，长句折行时能看见"先跳一下再滑"）。
- 补 **430ms 校正**：当前行字号有 0.4s 过渡，`centerLine()` 在过渡中读 `offsetHeight` 拿到中间值，实测首句偏 18px。
- 补 **`padding-top`**：`offsetTop` 从列的 padding 盒算起，中轴是整列中线，漏这一项窗口模式下每句偏低 8px。

实测（6 句歌词逐句 seek，每次等 1.3s）：补白恒为 `241px = 容器高/2`，当前句中心与容器偏差**全部为 0**，首句与尾句同样为 0。

## v0.5 点击进度条导致页脚下移

症状：每次点击（或按住）进度条，底部那一排按钮会往下掉一截，松手也不一定回来。

根因是**类名撞车**，和当初 `.mini` / `.line` / `.pop` 是同一类错误：

```css
/* 标题栏拖拽区 */
.drag { flex: 1; height: 100%; -webkit-app-region: drag; }
```

`renderer/app.js` 在进度条上按下时给 `.scrub` 加了 `drag` 类（表示"正在拖拽"），于是它也命中上面这条规则，按下瞬间计算样式从 `flex: 0 1 auto` 变成 `flex: 1 1 0%`、`height: 18px` 失效：

| 状态 | 窗口模式 | 全屏 |
| --- | --- | --- |
| 页脚高度 | 131.6 → 150 里 `.scrub` 从 18 撑到 66 | `.scrub` 被压到 4，页脚 131.6 → 117.6 |
| 按钮行位置 | 608 → 632（下移 24px） | 979 → 993，主区同时多吃 14px |

全屏下更糟：进度条塌到 4px 并整体下移 14px，鼠标松开时已经不在它上面，`pointerup` 收不到 → 拖拽态永久卡住，页脚一直矮 14px。

改了三处：

## v0.2.0 网易云音源 + 真实封面接入

### 数据是怎么映射的

新增 `player/netease.js`（主进程，纯 HTTP + 归一化，不碰 DOM），把网易云的歌 / 歌单 / 专辑映射到**现有 Track 结构**：

| 网易云 | Track | 缺失时 |
| --- | --- | --- |
| `id` | `path = "ne:<id>"`、`netId`、`source = "netease"` | 无 id 丢弃该条 |
| `name` | `title` | 「未知曲目」 |
| `artists[]` / `ar[]` | `artist`（多艺人 ` / `） | 「未知艺人」 |
| `album.name` / `al.name` | `album` | 空串 |
| `duration` / `dt`（ms） | `duration`（秒） | 0 → 列表 `—` |
| `album.picUrl` | `coverUrl`（https + `?param=WyW`） | 空 → 无封面占位 |
| `fee` | `fee` / `vip` | 只作提示 |

`path` 直接当唯一键复用：去重、封面缓存键、排序后下标重定位、写盘全都以 `path` 为准，所以网易云曲目和本地文件共用一套曲库逻辑，不用在每条链路加 `source` 分支。

两套接口字段不一致（`song/detail` 是 `artists/album/duration`，`playlist` 是 `ar/al/dt`，`search` 没有封面），映射层统一「多候选键 + 缺省值」；搜索后再批量补一次详情拿封面，补失败就退回无封面。

### 播放链路

`media:url` 对 `ne:` 前缀返回 `neaudio://s/<id>`，主进程：

1. 解析真实地址（缓存 5 分钟，接口给的直链 20 分钟过期）；
2. **透传 Range** —— 不转发 Range，进度条拖拽就退化成重新加载；
3. 命中 401/403 丢掉缓存换一条再试一次。

实测 `audio.seekable.end(0) = 270.8`，seek 到 20s 后 1.6s 为 21.55s，说明 Range 真的通了。

### 封面与 Palette

封面只有一个入口 `loadArt()`：本地读内嵌/同名文件（`trackDetail.cover`），网易云读 `coverUrl`（主进程下载成 data URL，`ne:cover`）。三条来源最后都是同一个 `src`，所以取色只有一份实现。

为什么不在 `<img>` 上直接写 https 地址：CSP 只需放开 `data:` 不必逐个 CDN 加白；canvas 取色不会被跨域污染；同一首歌切回来不重复拉图。注意 CDN 返回的是非标准 `image/jpg`，要归一成 `image/jpeg`。

Palette 语义也对齐了方案 6.5：取不到返回 `null` → 调用方降级中性色；取到但封面黑白 → 返回中性灰。两者原因不同，文案也不同（`暂无封面 / 网易云没有为该曲目提供封面` 与 `封面加载失败 · 已用中性底色`）。

### 边界情况

| 情况 | 实际表现 |
| --- | --- |
| 没封面 | `.cover.empty` + 「暂无封面 / 网易云没有为该曲目提供封面」，主色 `#5B5B66`，不加载任何硬编码图片 |
| 封面 404 / 非图片 / 过大 | 「封面加载失败 · 已用中性底色」，5 分钟内不重试，播放不受影响 |
| 封面下载中 | 「正在加载封面…」 |
| 时长/艺人/专辑缺失 | `—` / 「未知艺人」/ 留空 / 「未知曲目」 |
| 无时间轴歌词 | 提示「只有纯文本歌词，没有时间轴」；纯音乐提示「暂无歌词」 |
| 需登录 / 需会员 / 无版权 | 未登录：「需要登录后才有播放权限，扫码登录后再试」；已登录：「当前账号没有这首的播放权限（可能需要会员）」；自动跳下一首，**当前曲目与播放状态不变**；连续 3 次停止 |

| 歌单顺序 | 导入 `sort:false`，保持原顺序 |

## v0.2.1 登录改为手机扫码

### 为什么要改

v0.2.0 的做法是让用户去浏览器 F12 里翻 `MUSIC_U` 再粘贴进来。这不算登录，是把开发者的调试动作交给用户：路径长、容易粘错、粘错了也说不清错在哪一步。

现在走官方网页同一条扫码链路，主进程全程只碰**一次性 key** 和**登录后的会话串**，不碰账号密码。

### 链路

| 步骤 | 接口 | 说明 |
| --- | --- | --- |
| 取码 | `POST /api/login/qrcode/unikey?type=1` | 一次性 `unikey`，实测 71ms |
| 展示 | `https://music.163.com/login?codekey=<unikey>` | 本地生成 SVG，不联网取图 |
| 轮询 | `GET /api/login/qrcode/client/login?key=&type=1` | `801` 等待 / `802` 待确认 / `803` 成功 / `800` 过期 |
| 校验 | `GET /api/nuser/account/get` | `profile` 为 null 即凭证失效，结果缓存 60s |

### 几个必须踩对的点

1. **803 的 Cookie 只在响应头**。body 里的 `cookie` 字段不含 `MUSIC_U`，只读 body 会拿到空串还以为登录成功。拼接时剔除 `Max-Age=0` 的空项、同名只留第一条。
2. **二维码本地生成**。`qrcode-generator`（零依赖）算矩阵，自己合并每行的连续暗块、拼成一个 `<path>` 的 SVG（43×43 的码只 5 KB），渲染层 `innerHTML` 内联——CSP 不用给图片域名开口子，也不依赖任何二维码网站在线服务。
3. **固定白底黑块，不跟主题反色**。反色或透明底在不少扫码器上认不出来。
4. **轮询要有 token**。关抽屉、刷新、重开都要作废在途响应，否则会出现「已经关掉的码又跳成已扫码」。
5. **有文件 ≠ 已登录**。cookie 会过期而 `ne-auth.bin` 还在，靠 `account/get` 的 `profile` 判断，界面才敢说「登录已过期」。
6. **刚登录别立刻自我校验**。803 后马上打 `account/get` 有竞态，容易把「刚登录成功」判成「已过期」：先用 803 自带的昵称落 UI，60s 后再校准。
7. **落盘失败不算登录失败**。密钥库不可用时本次会话照常能播，只是要老实说「重启后需重新扫码」，不能假装成功。

### 界面

设置 → 网易云 → 「扫码登录」内嵌一张二维码卡片：等待扫码（灰）→ 已扫码待确认（绿）→ 过期（码压暗 + 遮罩 + 红字，点码或按钮刷新）→ 成功（绿色 + toast + 1.4s 自动收起）。未登录时列表上方的提示可点，直接跳到扫码，不用先去设置里找。

### 验证

`demo/probe-login.js`（全链路）与 `demo/probe-login2.js`（交互边界）两个探针，结果见上一节第 5 条。二维码可扫性是**解码验证**的：把页面里那块 SVG 用 canvas 光栅化后交给 `jsQR` 反解，拿回的就是官方登录链接。

## v0.2.2 登录后自动加载账号歌单

### 做了什么

扫码成功那一刻起，主进程就按**当前账号**拉一次歌单。抽屉的「网易云」不再是空搜索框，而是一页：

```
推荐            [每日推荐]  [私人FM]
推荐歌单 · 6 个   公开接口，未登录也有
我创建的歌单 · N   自己创建的，我喜欢的音乐置顶
```

点歌单展开曲目，点一条加入曲库并播放；「私人FM」的列表头有「换一批」。搜索框照旧：一输入就切到搜索结果，清空就回歌单页。

### 接口

| 用途 | 接口 | 需要登录 |
| --- | --- | --- |
| 我的歌单 | `/api/user/playlist?uid=&limit=500&offset=` | 是 |
| 推荐歌单 | `/api/personalized/playlist?limit=6` | 否 |
| 每日推荐 | `/api/discovery/recommend/songs` | 是 |
| 私人FM | `/api/radio/get` | 是 |
| 打开歌单 | `/api/v6/playlist/detail` + `/api/song/detail` | 视歌单 |

### 几个必须踩对的点

1. **只列自己创建的**：`creator.userId === uid && !subscribed`。收藏的歌单不进这段列表，否则几十个歌单混在一起根本找不到自己的；隐藏了几个收藏要在底部说明，不然用户以为数据丢了。
2. **803 之后没有 uid**。扫码成功只回昵称，`profile` 生效有毫秒级延迟。所以 803 时立刻起一个 6 次 / 400ms 上限的 uid 预热，拉歌单先等它，等不到再补两次；仍拿不到就提示「稍后重试」，**绝不拿 uid=0 去请求别人的歌单**。
3. **缓存按 uid 分键**。歌单 2 分钟、每日推荐 5 分钟、推荐歌单 10 分钟；`setCookie` 一律清空。渲染层每次请求带 `seq`，换账号后晚到的旧响应直接丢，否则会出现「新账号的名字配旧账号的歌单」。
4. **两段各自失败**。`home()` 用 `allSettled` 并发取「我的歌单」与「推荐歌单」：推荐挂了不影响我的歌单；只有账号接口本身失败（网络 / 5xx）才整页进错误态，给一条「歌单加载失败：原因 + 重试」，不留半截界面。
5. **登录失效要能指路**。`301 / -462` 统一翻成 `NE_LOGIN_REQUIRED`，界面区分「从未登录」与「登录已过期」，两种都给「扫码登录」按钮。
6. **封面是装饰**。下不回来就保留首字底色，不报错、不占位、不阻塞列表；一次最多 4 个在飞，20 个歌单不会同时压 20 个请求。

### 状态一览

| --- | --- | --- |
| 加载中 | 3 行骨架 | 2 行骨架 |
| 已登录有数据 | 逐行「封面 + 名称 + N 首」 | 6 行，副信息为播放量 |
| 已登录空歌单 | 「这个账号还没有创建歌单」 | 正常 |
| 未登录 | 登录提示 + 扫码按钮 | 正常（公开数据） |

| 接口失败 | 整页「歌单加载失败：原因」+ 重试 | 同左 |

## v0.2.3 音质可切 + 曲库列表封面

### 一、为什么之前「切了没反应」

不是界面没接上——老版本压根没有档位可选，而且真正的原因在接口层：

| 接口 | 传 `level` | 实际行为 |
| --- | --- | --- |
| `/api/song/enhance/player/url`（v0） | 传了 | **被忽略**，永远按 `br` 返回；传 `level=standard` 仍回 320k |
| `/api/song/enhance/player/url/v1` | 传了 | 生效：`standard`→128k、`higher`→192k、`exhigh`→320k |

所以现在固定走 v1；v1 整体不可用（改版 / 5xx）才退回 v0 + `br`，保证最差也能按码率降级、不会整首放不出来。

无损要会员权限，没有权限时接口**不报错，静默回 320k MP3**。因此界面同时列「请求音质」和「实际码率」，降级时直接写「账号没有『无损』权限，已按实际可用的 320 kbps 播放」，toast 也带真实码率——只写档位等于骗人。

### 二、五个必须踩对的点

1. **缓存按档位分键**（`<id>|<level>`）。地址缓存不带档位的话，切档拿到的还是上一档直链，等于没切；`setQuality` 一律清空整表。
2. **主进程也要知道当前档位**。`neaudio://` 解析地址用的是主进程那一份，只在渲染层改设置，会出现「本地曲目上选的档位」下次播网易云时对不上。`settings:set` / `settings:set-sync` 都同步给音源层，启动时从 `settings.json` 读回。
3. **换档 = 换流，不重播**。重新解析地址 → 重设 `audio.src` → `loadedmetadata` 后回到原 `currentTime` → 原来在播才继续播。不走 `playIndex`：那会把封面、歌词、主色全部重来一遍，界面闪一下，而且「暂停中换档」会被强行变成播放。
4. **本地文件不受影响**。`media://` 直接读文件，切换时明确提示「本地文件按原文件播放」，不做能点但无效的假开关。
5. **弹层贴边**。档位 + 实测两段加起来比窗口还高：`.pop` 加 `max-height + overflow` 自己滚；定位改用 `clientWidth/Height`（`innerWidth` 含滚动条，面板会压在滚动条下面），并用 `ResizeObserver` 兜字体加载/滚动条带来的尺寸变化——只在打开那一刻算一次，就会出现「右边贴着窗口」或「底部出屏」。

### 三、曲库列表的专辑封面

- **先占位再取图**：每行左侧是「首字磁贴」（中性底色 + 极淡内描边），不请求、不阻塞渲染。
- **只给可视区取**：IntersectionObserver 观察（含一屏 `rootMargin` 预取），并发上限 4，结果按 `path` / `coverUrl` 缓存。实测 **400 首列表只发出 13 个请求**。
- **主进程缩到 96px 再回传**：内嵌封面动辄几 MB，`nativeImage.resize({width:96})` 转成十几 KB 的 data URL，按路径 LRU 240 缓存；同目录 `cover.jpg` 走同一条路径。
- **缺失/失败保留占位**：不报错、不留空槽、行高不变（封面与占位同为 38×38）。

## v0.3.0 全量审计 + 安装包

这一版没有加新功能，只做三件事：把「异常路径」挨个跑一遍、修掉查出来的问题、把程序打成能装到别的电脑上的安装包。

### 修掉的问题

| # | 问题 | 触发条件 | 修法 |
| --- | --- | --- | --- |
| 1 | 设置/曲库读取失败会导致整个界面不初始化（白屏且无提示） | `settings.json` 权限异常、IPC 出错 | `init()` 全程兜底：读不到就用默认值，字段逐个校验类型与范围（`volume` 越界会让 `audio.volume` 抛 `IndexSizeError`） |
| 2 | 空曲库按方向键抛 `InvalidStateError` | 没有曲目时按 ←/→ | `seek()` 先判 `audio.duration` 是否有限；`prev()` 也加空库提示 |
| 3 | 换音质期间切歌会把音频源改回旧曲目 | 点档位后 100ms 内点下一首 | 每次 `await` 后校验「还是同一首歌」，不是就直接放弃 |
| 4 | `bytes=-N` 形式的 Range 被当成 `0..N` | 播放器/插件请求尾段字节 | 正确解析后缀区间；空文件返回 416 |
| 5 | 并发扫描时第二次调用拿到空数组，界面提示「没有新的音频文件」（其实是没扫） | 扫描大目录时又拖入文件 | 渲染层加扫描锁，第二次明确提示「正在扫描，请稍候」 |
| 6 | 播放失败提示不说是哪首、什么格式 | 坏文件 / 不支持的编码 | 提示带上曲名与编码 |
| 7 | 键盘监听只排除了 `INPUT`，在 `TEXTAREA`/可编辑区里按空格会触发播放 | 极少 | 补 `TEXTAREA`/`SELECT`/`contenteditable` |
| 8 | 主进程未捕获异常静默消失（打包后连控制台都没有） | 任意 main 侧异常 | 写 `%APPDATA%\NckiksMusic\crash.log`（目录不存在也能写，>512KB 自动滚动）；渲染进程崩溃自动 reload 一次 |
| 9 | 网络错误直接把 `ECONNREFUSED / ENOTFOUND` 甩给用户 | 断网、代理、DNS 异常 | 按错误码翻成「连不上 / 连接被拒绝 / 超时 / 网络不可达」 |
| 10 | 打包后任务栏显示 `electron.app.Electron` | 未设 AppUserModelID | `app.setAppUserModelId('com.yun.music.player')` |

### 打包配置

- `electron-builder` 26.x，目标 `nsis` x64，**非 oneClick**（可选安装目录）、**per-user**（不需要管理员权限）、桌面 + 开始菜单快捷方式。
- `asar: true`，但把 `music-metadata` 及其依赖链 `asarUnpack` 出来 —— 它是纯 ESM，动态 `import()` 从 asar 里读有踩坑风险，解包后与开发环境完全一致（已在安装后的产物里实测元数据解析正常）。
- `files` 白名单只收运行必需文件；`demo/`、`screenshots/`、文档、各类探针都不进包。
- 图标由 `make-icon.js` 用 zlib 手写 PNG（512×512），不引图形库。
- **不含苹方字体**（授权原因，见「字体」）—— v0.4.0 起已改为随包分发，见字体章节。

## v0.4.0 更名 + 字体随包 + 新图标

### 名称统一为 Nckik′s music

窗口标题、`<title>`、关于页、安装包产品名、桌面/开始菜单快捷方式、卸载显示名，全部统一。两个刻意的不一致：

- npm 包名用 `nckiks-music`（npm 不允许大小写和特殊字符）；
- **数据目录用 ASCII 名 `%APPDATA%\NckiksMusic\`**——路径里出现 `′`（U+2032）会给备份、同步和命令行工具找麻烦。实现上必须「仅在 userData 还等于按应用名推出来的默认值时才改道」：用户显式传 `--user-data-dir`（多配置/调试）时不能吃掉这个指定——这条是探针抓出来的回归（无条件覆盖曾让所有测试的临时目录被本机真实数据污染）。

改名必然换数据目录，启动时会做一次性迁移：新目录没有 `library.json / settings.json` 时，从旧目录（`云音乐` / `yun-music-player`）把三份文件（曲库、设置、加密凭证）搬过来，**有数据才迁、绝不覆盖**。测试环境设 `NCKIK_SKIP_MIGRATION=1` 可跳过。

### 苹方全局生效

字体 11 MB 随包分发（`build.files` 不再排除），配套三处改动：

1. `--font-ui` 单点定义，正文/按钮/输入框/弹层全部走它；表单控件默认不继承字体，所以对 `button / input / select / textarea` 显式指定了一遍，否则「导入文件 / 搜索框 / 音质档位」会掉回系统字体；
2. `font-display: swap`——字体万一缺失/损坏也不允许「有布局没文字」，先显示系统字体再替换；
3. 兜底栈 `Microsoft YaHei UI → Segoe UI → system-ui`。

验证：`document.fonts.check('16px "PingFang"')` 为真，body / 播放按钮 / 搜索框 / 设置按钮的 computed font-family 全部以 PingFang 开头（`demo/probe-brand.js`，14 项）。

### 图标：白底 + 一笔红色音符

`make-icon.js` 重写：白底圆角方块，红色（#E23A2E）一笔画完的八分音符——起笔符尾 → 符干 → 符头闭环，全程不抬笔。设计坐标（路径与笔宽同一套单位）整体缩放到各尺寸；多尺寸预览（16→256，`build/icon-preview.png`）是验收标准：16px 允许环填成点，轮廓必须仍是音符。

实现踩过两个坑，都留在注释里：笔宽与路径比例失配会把符头小环糊成实心；符头圆心放错方向（符干右上）会让整枚图案读成「b / 6」。
